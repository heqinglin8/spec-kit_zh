# Speckit 英译中

## 用户输入

```text
$ARGUMENTS
```

在执行前必须先解析并考虑 `$ARGUMENTS`。
若 `$ARGUMENTS` 包含 `--force`，则启用强制覆盖模式。

## 参数解析约定

1. 支持以下等价写法：
   - `路径 --force`
   - `--force 路径`
2. `--force` 仅作为布尔开关，不接收额外值。
3. 若出现多个路径参数，默认使用第一个有效路径，其余参数忽略并在输出中提示。
4. 若未提供有效路径，应报错并终止执行。
5. 若重复出现 `--force`，按一次处理，不视为错误。

## 目标

将指定路径下的 Markdown 技术文档翻译为中文，同时保留文件路径、技术术语、行内代码与代码块内容不变。

## 翻译规则

1. 如果目标路径是文件夹，则处理该文件夹或者子文件夹下的 `.md` 文件。保存在当前目标文件夹下建立的 `zh/`子文件夹。
2. 如果目标路径是文件，则只处理该文件本身。保存到本文件同级目录 `zh/` 子文件夹。
3. 输出文件命名为 `xxx.zh.md`
4. 不翻译文件路径、技术术语，以及反引号中的内容。
5. 不翻译 fenced code block（围栏代码块）中的内容，例如：

```text
$ARGUMENTS
```

1. 双引号内若为描述性英文可翻译；若为变量或技术术语则保持不变。 
2. 若某句无法翻译为通顺中文，可保留原文。 
3. 默认情况下，若目标 `xxx.zh.md` 已存在，则跳过该文件。 
4. 若 `$ARGUMENTS` 包含 `--force`，则无论目标文件是否存在，都执行覆盖写入。 
5. 完成后输出实际生成或覆盖的翻译文件路径。

## 执行步骤

1. 解析 `$ARGUMENTS`，获取目标路径，并识别是否包含 `--force` 标记。
2. 校验路径是否存在，并识别类型（文件夹或文件）；无效则返回错误。
3. 根据路径类型构建待翻译源文件列表。
4. 逐个处理源文件：
   - 若未开启 `--force`：检查 `zh/xxx.zh.md` 是否已存在，存在则跳过；
   - 若开启 `--force`：即使 `zh/xxx.zh.md` 已存在，也继续翻译并覆盖；
   - 读取 Markdown，仅翻译语义描述文字；
   - 保持原有结构（标题、列表、表格、链接、行内代码、代码块）；
   - 将结果写入 `zh/xxx.zh.md`。
5. 返回所有新生成或被覆盖的翻译文件路径。

## 示例（中文）

1. 当输入路径为文件夹（如 `docs/`）时，在 `docs/zh/` 下生成对应的 `xxx.zh.md` 文件，并输出生成路径。
2. 当输入路径为文件夹（如 `docs/`）时，并且在`docs/`下有`d1`和`d2`子文件夹，则在 `docs/zh/` 下生成对应的 `docs/zh/d1/xxx.zh.md` 文件和`docs/zh/d2/xxx.zh.md`，并输出生成路径。
3. 当输入路径为文件（如 `docs/spec.md`）时，在 `docs/zh/` 下生成 `spec.zh.md`，并输出生成路径。
4. 当输入为 `docs/ --force` 时，即使 `docs/zh/` 下已有 `.zh.md` 文件，也会覆盖更新并输出覆盖路径。

## 输出格式

- 成功：逐行列出生成的文件路径。
- 成功（`--force`）：逐行列出生成或覆盖的文件路径。
- 全部跳过：明确提示未生成新文件。
- 失败：给出具体失败路径与原因。
